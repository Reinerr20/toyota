# Troubleshooting

Run diagnostics from the repository root and avoid real uploads or hardware actuation unless the test is explicitly approved.

| Symptom | Likely cause | Diagnostic check | Resolution | Escalation evidence |
| --- | --- | --- | --- | --- |
| Application fails to start | Missing dependency, wrong environment, invalid YAML/value, or wrong working directory | `python -m compileall -q main.py src`; confirm `config/runtime_config.yaml` and `config/detector_config.yaml` exist | Activate the approved environment; run from the repository root; restore a valid reviewed setting | Full traceback, Python/platform version, redacted configuration, exact command |
| `Camera failed to open` | Wrong source/index, permission, busy device, missing Picamera2, or disconnected camera | `python -m src.infrastructure.hardware.camera`; review `DS_CAMERA_SOURCE`, `DS_CAMERA_INDEX`, and `DS_CAMERA_RES` | Select `opencv`/correct index or `picamera2`; release the device from other processes; correct OS permissions | Camera model, source/index, diagnostic logs, OS device listing |
| No detection event | Calibration/identity not complete, face/eyes not visible, threshold/persistence not met, or event rule not triggered | Watch mode/calibration/status logs and review `config/detector_config.yaml` | Restore framing/lighting; use the intended identity mode; change thresholds only through a controlled validation plan | Redacted logs, configuration, scenario description, representative consented sample reference |
| Buzzer does not sound | Disabled flag, wrong BCM pin/wiring, missing `gpiozero`, or no GPIO permission | Check for `Buzzer disabled`, `gpiozero unavailable`, or initialization warnings; only with approval run `BUZZER_PIN=17 python src/infrastructure/hardware/buzzer.py` | Correct reviewed wiring/pin and OS permissions; set `DS_BUZZER_DISABLED=0` | Wiring diagram, board model, pin, logs, standalone result |
| GPS has no data/fix | Wrong serial port/baud, permission, wiring/antenna, or no sky view | `python -m src.gps.standalone_test --port /dev/ttyAMA0 --baud 9600` | Correct port/baud/permissions and antenna placement; allow acquisition time in a safe location | Redacted NMEA/diagnostic logs, receiver model, port settings, test conditions |
| Compass unavailable or heading implausible | Unsupported/missing I2C device, address/bus mismatch, mounting offset, declination, or magnetic interference | `python -m src.compass.standalone_test`; inspect configured bus/address/offset | Correct I2C access and configuration; calibrate away from interference before publishing heading | Chip/address, I2C wiring, raw values, mounting orientation, test location |
| Driver ID is inconsistent | Enrollment/operation mismatch, insufficient face view, recognition timing, or user-profile quality | Confirm `DS_IDENTITY_MODE`; inspect recognition/mismatch logs and local `users` count without exporting face blobs | Use operation mode when identity binding is not required; repeat approved enrollment with stable framing | Mode, redacted logs, lighting/eyewear/pose conditions, profile IDs only |
| Event is not stored | Database path/permission, disk full, schema/lock error, or logger failure | Review `Failed to save event`; query `data/cc.db` using the command in [Setup and Run](SETUP_AND_RUN.md) | Correct path, permissions, and free space; stop duplicate writers; preserve the DB for analysis | Logs, resolved DB path, free space, schema via `PRAGMA table_info(events)` |
| Upload is delayed or fails | Remote disabled, unreachable URL, timeout, server rejection, queue backlog, or payload too large | Inspect `remote_sent`, `remote_attempts`, `remote_last_error`, and `delivery_status` in SQLite; review `[REMOTE]` logs | Correct the controlled endpoint/network; keep the DB intact for retry; disable images if policy permits and HTTP 413 persists | Redacted URL, HTTP status/error, row ID and delivery fields, timestamps |
| Evidence does not synchronize | Image missing/compression failure, evidence retries disabled/exhausted, or server rejection | Inspect `evidence_sent`, `evidence_attempts`, `evidence_last_error`, `evidence_upload_failed`, and `evidence_next_retry_at` | Correct endpoint/image policy; review retry settings; do not manually mark evidence sent | Event row ID, byte length, evidence fields, redacted server response |
| GPS/dashboard update is absent | No GPS fix, WebSocket unreachable, publishing disabled, or external contract mismatch | Check `DS_GPS_PUBLISH_ENABLED`, `GPS waiting for fix`, connection, and send logs | Restore a fix/network and use the reviewed WS URL/vehicle ID | Payload with location redacted, sequence/timestamps, connection error, external service logs |
| IMU unavailable or no candidate | Feature disabled, I2C issue, no GPS speed, below threshold, or cooldown | `python -m src.imu.standalone_test`; inspect `reason` in candidate output during an approved stationary/controlled test | Keep disabled until calibrated; correct bus/address and required GPS context | Sensor/chip/address, raw sample logs, orientation, GPS state, threshold configuration |
| Config/model resource error | Missing relative file or wrong working directory | Confirm referenced paths with `git ls-files`; run from repository root | Restore tracked files and use repository-root startup | Exact missing path, current directory, traceback, Git status |

Do not send real emergency notifications, fleet alerts, or production uploads as a troubleshooting test. Do not attach database files or cabin images to an issue without privacy approval.
